01 / Quick start

Connect a computer

A System Commander setup has two separate credentials: a private device credential between your computer and System Commander Cloud, and an OAuth session used by your AI client. Keep those two paths separate.

01

Create a device registration

Open System Commander Cloud, sign in, and add a computer from your dashboard.

02

Run the generated command

Cloud gives you the exact pairing command for that computer. Do not edit the device ID or token.

Example
npx @leukode-labs/system-commander@latest remote --relay https://system-commander-cloud-production.up.railway.app --device-id YOUR_DEVICE_ID --token YOUR_DEVICE_TOKEN
03

Leave the agent running

When the terminal reports that the local engine is ready and the device is connected, the computer is available to your authenticated MCP clients.

02 / MCP

Connect Claude or another MCP client

Your dashboard is the permanent place to retrieve the MCP URL for each computer. The URL identifies the device; the private device token is never the MCP credential.

MCP URL Open your System Commander dashboard, find the computer, and copy its MCP connection URL whenever you need it.
01

Copy the MCP URL from the dashboard

Use the computer card's Copy MCP URL action. It stays the same when you rotate the device token.

02

Add it to your MCP client

For Claude, use its custom connector flow and provide the MCP URL. Claude handles the OAuth authentication step with System Commander Cloud.

03

Test with a harmless request

Ask the AI to perform a read-only operation first, such as listing a directory or checking the current working directory.

03 / Local reset

Remove the saved device credential

Use this when you want to completely remove the locally saved System Commander device ID and token from a computer before starting over. Stop the running remote agent first.

Important This removes the credential saved on the computer. It does not revoke the cloud-side device record. Revoke the device from your System Commander dashboard when you also want to invalidate the cloud registration.
Windows · PowerShell
Remove-Item -Recurse -Force "$HOME\.system-commander-device"
Windows · Command Prompt
rmdir /s /q "%USERPROFILE%\.system-commander-device"
macOS · Linux
rm -rf "$HOME/.system-commander-device"

After removing the local credential, create a fresh registration in Cloud and run the new generated command. Do not reuse an old token from an earlier setup.

04 / Credentials

Rotate a device token

Token rotation keeps the device ID and MCP URL stable while replacing the private computer-to-cloud credential. Use your dashboard to generate a fresh token when the existing token is suspected to be stale or exposed.

After rotation The existing agent session is closed. Run the newly generated pairing command on the computer. Your MCP URL does not need to change.

05 / Troubleshooting

Common connection errors

DEVICE_NOT_REGISTEREDThe device ID is not present in the Cloud account. Create a fresh device registration and use the new command.
TOKEN_INVALIDThe local token does not match the cloud record. Generate a fresh token and run the exact command Cloud provides.
TOKEN_EXPIREDThe device credential reached its expiry time. Rotate the token and reconnect the agent.
Cloud connection failedVerify internet access and keep the relay URL exactly as supplied by System Commander Cloud.
